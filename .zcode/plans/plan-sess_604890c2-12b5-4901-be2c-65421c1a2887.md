## Implementation Plan: Electron.js Desktop App for mcode

### Goal

Create `packages/desktop/` — an Electron.js desktop application that wraps the existing mcode web frontend (React 19 + Vite) and spawns the backend (Express + Socket.IO + MongoDB) as a child process. The UI (Electron renderer) is fully separated from the CLI/backend (child process), exactly as requested: *"ui wale ko alag ker sakta he and cli wale ko bhi alag ker."*

### Architecture

```
┌──────────────────────────────────────────────────────────┐
│  Electron App (packages/desktop)                         │
│                                                          │
│  ┌──────────────────┐    ┌────────────────────────────┐  │
│  │ Main Process      │    │ Renderer (Web Frontend)     │  │
│  │ main.js           │    │ packages/web/src            │  │
│  │ • Spawns backend  │    │ • React 19 + Vite           │  │
│  │ • Health polls    │◄──►│ • Connects to localhost:3100│  │
│  │ • IPC handlers    │    │ • HashRouter               │  │
│  │ • OAuth popup     │    │ • axios + Socket.IO         │  │
│  └───────┬───────────┘    └────────────────────────────┘  │
│          │                                                  │
│          ▼                                                  │
│  ┌──────────────────┐                                      │
│  │ Backend Process   │  ◄── Imports CLI modules ─────────  │
│  │ packages/backend  │     (ChatSession ↔ mcode-cli)        │
│  │ • Express :3100   │                                      │
│  │ • Socket.IO /live │                                      │
│  │ • MongoDB Atlas   │                                      │
│  └──────────────────┘                                      │
└──────────────────────────────────────────────────────────┘
```

The backend child process is started with `node packages/backend/src/main.js` and inherits env vars from `packages/backend/.env`. If MongoDB is missing, the backend exits and the Electron window shows a first-run setup dialog.

### Phase 1: Create packages/desktop/

**Files:**

1. **`packages/desktop/package.json`** — `@mcode/desktop` v2.4.6 with `electron` and `electron-builder` as devDependencies. Workspaces auto-picks up `packages/*`.

2. **`packages/desktop/electron/main.js`** — Electron main process:
   - Spawns backend as child process: `spawn(process.execPath, [backendMainJs], { env: {...process.env, PORT: '3100'} })`
   - Polls `http://localhost:3100/health` every 500ms (max 30s) before showing the window
   - Creates BrowserWindow (1400×900, min 1000×600, `contextIsolation: true`, `nodeIntegration: false`, `preload`)
   - Dev: loads `http://localhost:5173` (Vite dev server); Prod: loads `file:///<web-dist>/index.html`
   - IPC handlers: `open-oauth-popup`, `open-external`, `select-directory`, `show-error-in-window`
   - Registers `mcode://` custom protocol for deep linking
   - Kills backend child process on app before-quit

3. **`packages/desktop/electron/preload.mjs`** — contextBridge exposing `window.mcodeElectron`:
   - `backendUrl: 'http://localhost:3100'` — so axios and Socket.IO connect explicitly
   - `isDev: boolean`, `isPackaged: boolean`
   - `openOAuthPopup(url)` → creates popup BrowserWindow, intercepts `will-redirect` for `github_connected` param
   - `openExternal(url)` → `shell.openExternal`
   - `selectDirectory()` → `dialog.showOpenDialog`
   - `onTokenReceived(callback)` → IPC listener for OAuth token injection

4. **`packages/desktop/index.html`** — minimal HTML shell with `<div id="root"></div>` for prod mode (dev uses Vite's own `index.html`)

### Phase 5: MongoDB and first-run handling

The backend requires `MONGODB_URI` and calls `process.exit(1)` if it's missing (`db.js:28-32`).

**Approach:**
1. Electron main process reads `packages/backend/.env` (or creates from `.env.example`)
2. Sets all env vars when spawning the backend child process
3. If health check fails (backend exited due to missing MongoDB), show a first-run dialog in the Electron window collecting: `MONGODB_URI`, `JWT_SECRET`
4. Restart the backend with the new env vars
5. **Optionally** for development: install `mongodb-memory-server` as a fallback — the Electron app can start an in-memory MongoDB and set `MONGODB_URI` to its connection string automatically

### Phase 6: OAuth flow in Electron (GitHub Connect)

No backend changes needed for MVP:

1. User clicks "Connect GitHub" in the web UI
2. `useChatSocket.js`/`AIChatPage.jsx`/`SettingsPage.jsx` calls `window.mcodeElectron.openOAuthPopup(url)`
3. Main process creates a 400×600 BrowserWindow, navigates to `http://localhost:3100/api/v1/auth/github?token=<access>`
4. Backend redirects to GitHub OAuth
5. User authenticates → GitHub redirects back to backend callback
6. Backend saves token to MongoDB → redirects to `http://localhost:5173/ai/chat?github_connected=1`
7. Popup's `will-redirect` handler captures the URL, detects `github_connected=1`, fires IPC event to renderer
8. Popup closes → renderer refreshes GitHub status via `GET /api/v1/github/status`

### Phase 7: Startup animation (matching ZCode reference)

Replicate the ZCode startup animation documented in `ZCODE-KNOWLEDGE-BASE.md`:
- Show a splash/overlay with logo pop animation (720ms, `cubic-bezier(0.22, 1, 0.36, 1)`) on window creation
- Fade in the React app once it dispatches a "ready" event (via IPC: `window.mcodeElectron.onReady()`)
- This matches zcode's 2-stage startup: logo animation → React ready → fade out overlay
