## Web Chat + AI Code Agent — Implementation Plan

### Goal
Add a Chat/Agent toggle to the dashboard. **Chat mode** = plain LLM conversation (no tools). **Agent mode** = full Cursor/ZCode IDE-style interface with file tree, code editor, chat pane, and real-time tool execution (read/write/edit/shell/search/test/git). Backend reuses CLI's ChatAgent + ToolExecutor + ModelRouter + providers — no rewriting from scratch.

---

### Phase 1: Backend — CLI Core Bridge + Chat Socket Handlers

#### 1a. CLI Subpath Exports (`packages/cli/package.json`)
Add exports map so backend can import individual modules:
```json
"exports": {
  ".": "./dist/mcode.mjs",
  "./orchestrator": "./src/core/orchestrator.js",
  "./chat-agent": "./src/core/chat-agent.js",
  "./tools": "./src/core/tools.js",
  "./router": "./src/core/router.js",
  "./providers": "./src/providers/index.js"
}
```
Backend adds `@mcode/cli` as a workspace dependency.

#### 1b. API Key Management — Encrypted in MongoDB
New route: `GET/POST/DELETE /api/v1/keys`
- Schema: `{ userId, providerId, envVar, encryptedKey }` (AES-256-GCM)
- `GET /keys` → list user's saved keys (masked, like CLI's vaultList)
- `GET /keys/models` → list all available models from configured providers
- `POST /keys/test` → verify a key against a provider
- Reuses CLI's `getAllAdapters(secrets)` — backend passes user's decrypted keys as `secrets`

#### 1c. Workspace Management — ZIP Upload + Git Clone
New route: `/api/v1/workspaces`
- `GET /workspaces` → list user's workspaces
- `POST /workspaces` → create from ZIP or Git
  - **ZIP tab**: upload .zip → backend extracts to `~/mcode-workspaces/<id>/`
  - **Git tab**: repo URL input + branch selection (current / new with custom name) → `simple-git` clone + checkout
- File API: `GET /workspaces/:id/files`, `GET /workspaces/:id/file?path=...`, `PUT /workspaces/:id/file?path=...`

#### 1d. Socket.IO Chat Handler (in `sockets.js`)
Extends existing Socket.IO server with chat handlers:

**`chat:start`** — Backend creates per-connection EventEmitter as `bus`, loads user's API keys from DB, calls `getProviders({ secrets })` + `new ModelRouter(...)`. If no keys → emit `chat:error` with red warning "please select your api keys to use mcode". Store session context on socket.

**`chat:send`** — Payload: `{ prompt, mode }`
- **Chat mode**: `router.pick('general')` → `provider.stream()` → chunks → `socket.emit('chat:stream', { text })`
- **Agent mode**: `router.pick('build')` → `new ChatAgent({ assignment, projectPath, bus, undoStack, config })` → `agent.run(prompt)`.
  - ChatAgent emits on `bus`: `EVENTS.MESSAGE` (stream/tool/system/summary/permission)
  - Backend listens to bus → `socket.emit('chat:message', msg)` for each event
  - **Key insight**: ChatAgent already uses an EventEmitter as `bus` with all the block metadata (path, lines, diffLines, command, output). Backend just bridges bus → Socket.IO.

**`chat:permission_answer`** — Backend: `bus.emit(EVENTS.PERMISSION_ANSWER, { requestId, answer })` → resolves ChatAgent's `_askPermission`

**`chat:interrupt`** — Calls `chatAgent.abort()`

#### 1e. Chat Session Persistence
- Store transcripts using existing `Session` model
- New `ChatMessage` schema: `{ sessionId, role, content, kind, block, timestamp }`

### Phase 2: Frontend Dashboard — Cursor/ZCode-Style IDE UI

#### 2a. Redux Store — `chatSlice.js`
State: `messages[]`, `isGenerating`, `mode` ('chat' | 'agent'), `workspace`, `models[]`, `selectedModel`, `streamingText`, `pendingPermission`, `toolCalls[]`

#### 2b. New Route: `/app/chat`

**Layout**:
```
Chat Mode (simple):
┌─ [Chat●Agent] [Model] [Workspace▼] ──┐
├─ MessageList (chat bubbles) ─────────┤
├─ Input: textarea + send ─────────────┤
└──────────────────────────────────────┘

Agent Mode (full IDE):
┌─ [Chat|Agent●] [Model] [Workspace▼] ──┐
├─ FileTree │ MessageList │ AgentPanel ─┤
├─ Input: textarea + send + interrupt ──┤
└──────────────────────────────────────┘
```

**Components**:
1. **ChatTopBar** — Chat/Agent toggle, model selector (ModelSelectorModal), workspace dropdown, red warning banner when no keys
2. **FileTreeSidebar** — recursive file tree, click to view file
3. **MessageList** — renders message kinds (mirrors CLI's blocks.jsx):
   - `kind: 'user'` → chat bubble
   - `kind: 'assistant'` → streaming text + metadata footer
   - `kind: 'tool'` → ReadBlock/WriteBlock/DiffBlock/CommandBlock (reuses dashboard's `CodeBlock`)
   - `kind: 'system' | 'ok' | 'err' | 'warn'` → inline messages
   - `kind: 'summary'` → file change summary
4. **AgentSidebar** (right) — real-time tool call strip, reuses existing `AgentSidebar.jsx`
5. **InputBar** — textarea, send button, interrupt, model display
6. **ModelSelectorModal** — provider list + API key entry (mirrors CLI's ProviderWizard)
7. **PermissionModal** — Allow/Deny/Always Allow, 60s timeout
8. **WorkspaceModal** — ZIP upload or Git clone tabs

#### 2c. Socket.IO Chat Client (`socket/chatSocket.js`)
- Connect with JWT token
- Listen for: `chat:stream`, `chat:message`, `chat:permission`, `chat:done`, `chat:error`
- Emit: `chat:start`, `chat:send`, `chat:permission_answer`, `chat:interrupt`

#### 2d. Routing Integration
- Add `/app/chat` route to dashboard `App.jsx`
- Add "Chat" nav item in `AppShell.jsx`

`chat:start`, `chat:send`, `chat:permission_answer`, `chat:interrupt` (client→server) and `chat:stream`, `chat:message`, `chat:permission`, `chat:done`, `chat:error` (server→client).

- Socket.IO test: emit chat:send → verify events forwarded
- API key encryption round-trip test
- Workspace: ZIP extract, Git clone, file listing
- Permission flow: prompt → client answer → ChatAgent continues

- Token/cost tracking in top bar (reuse CostLedger)

### Reuse Summary (no new logic):
- **ChatAgent** — backend imports & instantiates directly
- **ToolExecutor** — used internally by ChatAgent
- **ModelRouter + getProviders + all 40+ provider adapters** — reused as-is
- **EventEmitter bus** — ChatAgent's bus bridges 1:1 to Socket.IO
- **Dashboard UI components** — Card, Badge, CodeBlock, Button, Input, ToastStack all reused
- **CLI's blocks.jsx rendering patterns** — adapted to React components
- **CLI's ProviderWizard flow** — adapted to ModelSelectorModal
- **CLI's InputLine slash commands** — available in Agent mode
